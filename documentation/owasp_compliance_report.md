## OWASP Top 10 for Agentic Applications (2026) & Application Compliance

Vectra.ai emphasizes aligning with both the classic **OWASP Top 10 for LLMs** and the emerging **OWASP Top 10 for Agentic Applications**. Here is an analysis of how our Agentic Text2SQL & RAG application complies with the Agentic Top 10 risks:

| Risk | Description | Our Application's Mitigation | Compliance Status |
| :--- | :--- | :--- | :--- |
| **ASI01: Agent Goal Hijack** | Attackers manipulate the agent's objective via prompt injection to perform unintended actions. | **NeMo Guardrails** actively scans inputs for jailbreaks and blocks malicious prompts before they reach the orchestrator. | ✅ Strong |
| **ASI02: Tool Misuse & Exploitation** | Agents use legitimate tools in malicious or unintended ways (e.g., dropping databases). | **RBAC and HITL (Human-in-the-Loop)** are enforced. Sensitive SQL queries require explicit human approval before the `execute` node acts. | ✅ Strong |
| **ASI03: Identity & Privilege Abuse** | Exploiting the agent's credentials or escalating privileges. | Authentication is implemented via JWTs. The graph strictly checks `user_role` ("admin" vs "user"), isolating privileges per session. | ✅ Strong |
| **ASI04: Supply Chain Vulnerabilities** | Compromising the agent via malicious dependencies, models, or plugins. | All Python dependencies are strictly pinned in `requirements.txt`. The system relies on vetted primary LLMs (Gemini/OpenAI) using official SDKs. | ⚠️ Standard (Requires ongoing dependency scanning) |
| **ASI05: Unexpected Code Execution** | An agent successfully writes and executes malicious code (RCE) on the host. | The agent is tightly bounded to executing **only SQL** against a local SQLite database. No arbitrary Python execution tools are granted to the LLM. | ✅ Strong |
| **ASI06: Memory & Context Poisoning** | Attackers poison the vector store (RAG) to manipulate future agent responses. | **Microsoft Presidio** scrubs all PII from documents *before* they are embedded into the FAISS index, preventing sensitive data poisoning. | ✅ Strong |
| **ASI07: Insecure Inter-Agent Comm.** | Eavesdropping or spoofing communication between multi-agent nodes. | The application uses **LangGraph's TypedDict (`AgentState`)** for strongly typed, internal in-memory state passing, eliminating external spoofing risks. | ✅ Strong |
| **ASI08: Cascading Failures** | A failure in one agent loops or cascades, crashing the entire system. | **Max Step Limits** (`MAX_AGENT_STEPS`) prevent infinite LangGraph loops. **SlowAPI** rate limits incoming requests. | ✅ Strong |
| **ASI09: Human-Agent Trust Exploit** | Manipulating human users through phishing or false information generated by the agent. | **NeMo Output Guardrails** sanitize the LLM's final response, replacing harmful or deceptive outputs with safe defaults before the user sees them. | ✅ Strong |
| **ASI10: Rogue Agents** | Agents operating outside intended boundaries autonomously. | The **Deterministic StateGraph** ensures the agent cannot deviate from predetermined paths (e.g. Orchestrator -> Generate -> Validate -> Execute). | ✅ Strong |

### Summary
Our application is **highly compliant** with the current AI security standards. By implementing **NeMo Guardrails** (Goals/Trust), **Microsoft Presidio** (Poisoning/Privacy), **LangGraph constraints** (Cascading/Rogue), and **HITL/RBAC** (Tools/Identity), you have built a defense-in-depth architecture that successfully addresses the core concerns of the OWASP Top 10 for Agentic Applications.
